# terraform-provider-gpudeck

Terraform provider for the GPU Deck admin API (Go, terraform-plugin-framework, protocol v6).
Module `github.com/sur950/gpu-deck/apps/terraform-provider`; provider address
`registry.terraform.io/sur950/gpudeck`. Licensed under the [Apache License 2.0](../../LICENSE),

## Build and use locally

```bash
cd apps/terraform-provider
go build -o terraform-provider-gpudeck .
cat > ~/.terraformrc <<RC
provider_installation {
  dev_overrides { "registry.terraform.io/sur950/gpudeck" = "$PWD" }
  direct {}
}
RC
export GPUDECK_ENDPOINT=http://localhost:8180 GPUDECK_USERNAME=admin GPUDECK_PASSWORD=...
cd examples/complete && terraform plan
```

Release builds set the version with `-ldflags "-X main.version=1.2.3"` (GoReleaser, `.goreleaser.yml`, run by `.github/workflows/release.yml`).

## Authentication

`token` (`GPUDECK_TOKEN`, a session token such as the one `gpudeck login` stores) or `username` +
`password` (`GPUDECK_USERNAME` / `GPUDECK_PASSWORD`): the provider posts to `/auth/login` once and
keeps the `gpudeck_session` cookie value. Every Terraform command starts the provider again and
logs in again; the admin login is rate limited (10/min per IP), so automation that runs many
commands in a row (CI, acceptance tests) should pass a session token instead. All requests use `Authorization: Bearer`, which the
admin API accepts without a CSRF token. `insecure_skip_verify` (`GPUDECK_INSECURE=1`) is for lab
setups with self-signed certificates.

## Behaviour notes

- JSON-shaped settings (`config`, `params`, `launch_flags`, ...) are `jsonencode(...)` strings.
  When the server adds defaults to such an object the value in state stays as written, so plans
  stay empty; changing a key you set is still detected.
- Optional attributes left unset stay unset in state even though the API returns its default
  (for example `replicas = 1`); setting one explicitly to the default is the same thing.
- `gpudeck_rule.params` is validated at plan time against the embedded copy of
  `libs/contracts/rules/<type>.schema.json`.
- Secrets: `gpudeck_api_key.key`, `gpudeck_join_token.token` / `join_command` are returned once by
  the API and kept in state (sensitive). `gpudeck_alert_channel.secret` is never read back from
  the API (drift on it is not detected), but Terraform still stores the configured value in state
  (sensitive), so use an encrypted remote backend for state.
- `gpudeck_join_token` has no update: every change creates a new token; destroy revokes it.
  A token revoked elsewhere is created again on the next apply.
- `gpudeck_deployment.running` starts/stops through the dedicated endpoints;
  `wait_for_ready` waits for status `running`. Deletes are asynchronous; the provider waits until
  the deployment is gone (`wait_timeout_seconds`, default 600) and warns if it is still deleting.
- `gpudeck_cluster.status` is not accepted by the create endpoint; when set it is applied with a
  PATCH right after create.

## Layout

```
main.go                       provider server
internal/client/gen.go        generated by oapi-codegen v2.5.0 (never edit)
internal/client/client.go     login, Bearer auth, envelope decoding
internal/provider/spec.go     field specs -> schema, request bodies, state normalisation
internal/provider/resource_generic.go  CRUD for every resource
internal/provider/resources.go, deployment.go, datasources.go  the resources / data sources
internal/rulesschema/         embedded rule JSON Schemas + validation
tools/gen.sh                  regenerate gen.go and the rule schemas from libs/contracts
tools/docgen                  regenerate docs/ from the schemas and examples/
```

After a contract change: `go generate ./...` (needs `uv` for the 3.1 -> 3.0 downgrade), adjust
the field lists in `internal/provider`, then `go run ./tools/docgen`.

## Tests

```bash
go vet ./... && go test ./...      # httptest fake admin API + terraform CLI from PATH
TF_ACC=1 GPUDECK_ENDPOINT=http://localhost:8180 GPUDECK_USERNAME=admin GPUDECK_PASSWORD=... \
  go test ./internal/provider -run TestAcc -v          # against a running control plane
```

Unit tests run the real provider through `terraform` against an in-memory admin API that mimics
the server behaviours the provider has to absorb (defaults, CIDR canonicalisation, one-time
secrets, async deployment status and deletion, paginated lists). `TestDocsUpToDate` fails when
docs/ is stale.

The module targets Go 1.25 (pinned dependency versions that do not require a newer toolchain).
